## F1 — BLOCKING: the check box is now unclickable (double-toggle to a no-op)

`overplot.py:228` connects `itemClicked` → `_toggle_item_checked`
(`:358-364`). Qt's `QStyledItemDelegate::editorEvent` **already** toggles
`checkState` when a release lands in the indicator rect, and
`QAbstractItemView::mouseReleaseEvent` emits `clicked(index)` **before**
its `if (edited) return`. So an indicator click fires both: the delegate
toggles, then the slot toggles back. Net change: zero.

Verified twice, independently. Integrator probe (`QTest.mouseClick` on a
bare `QListWidget` reproducing lines 139/228/358-364):

```
click on CHECK INDICATOR -> checkState=0 (unchanged)  itemClicked fired=1
click on TEXT BODY       -> checkState=2 (toggled)    itemClicked fired=1
```

Blocking reviewer's sweep across the row, plus a control run with the
connection removed:

```
x+2,+20 (indicator edges) -> TOGGLED      x+5,+8,+12,+16 -> NO CHANGE
x+30    (text area)       -> TOGGLED
three clicks squarely on the indicator from Unchecked -> NO CHANGE (x3)
control, same widget WITHOUT the itemClicked connection: x+8 -> TOGGLED
```

The control proves the cause is the new connection, not `NoSelection`.

**User-visible failure.** A scientist clicks the check box next to
`REFL_198409_combined.txt` — the one affordance v2 declares is "the only
notion of a chosen file" — and nothing happens. Clicking the *filename
text* works, so the behavior is erratic and undiscoverable. The natural
recovery is to assume the click missed, believe the file is checked, press
Refresh, and get no replot: **B3's own "I asked for fresh data and nothing
changed" experience, reached by a new route.** It is also a regression
against deployed `exp`, where clicking a row did something.

**This is a defect in the plan's prescribed mechanism, faithfully
implemented.** The plan's v2 section specifies exactly `NoSelection` +
`itemClicked` → toggle. Closing it needs an **Analyst amendment**, not
only a code edit — which is why this routes back rather than being a
note in a PR body.

**Fix (minimal, provably correct).** Delete `:228` and
`_toggle_item_checked`; keep `NoSelection` and the `or item.isSelected()`
removal. The check box then works natively (control run above), the
check-only snapshot in `refresh()` stays coherent by construction, and the
keyboard path is unaffected. Cost: clicking the row *text* no longer
toggles — which never worked on `exp` either. If whole-row toggling is
wanted, it cannot come from `itemClicked` (which carries no position):
install a viewport event filter on `MouseButtonRelease` and toggle only
when the release point is **outside**
`style().subElementRect(QStyle.SE_ItemViewItemCheckIndicator, opt, view)`,
letting the delegate own indicator clicks.

**Why no test caught it.** `test_row_click_toggles_check`
(`test_overplot_refresh.py:142,144`) calls `itemClicked.emit(item)`, which
bypasses the delegate entirely — it tests the slot, not a click. Replace
with a real `QTest.mouseClick` at the indicator rect; that test fails
today.

## F3 — advisory, but the same class as v1's B4 and one condition from closed

`save_settings` guards on *emptiness*, not *validity*:
`read_settings` accepts a stored folder only when `os.path.isdir()` holds
(`:240`), while `save_settings` persists any non-empty string
(`:260-262`). The live path: type or paste a bad folder → `folder_changed`
(`:376-385`) warns "Folder does not exist" and **leaves the text in the
field** without saving → the user then touches the Plot-mode combo, an
unrelated control → `_on_plot_mode_changed` (`:404-412`) calls
`save_settings()` unconditionally → the bad path overwrites the good one.
Next launch: `isdir` fails, the field is empty, and the good path is gone.

One condition closes it:

```python
if folder and os.path.isdir(folder):
    self.settings.setValue("overplot_folder", folder)
```

Recommend fixing this in v3 alongside F1 — it is the same data-loss class
the slug was rejected for in v1.

## Remaining advisory findings

- **F2 — Refresh still stamps freshness over a stale canvas in a second
  path.** `refresh()` writes `overplot_last_refresh` and the tooltip
  (`:331-333`) *before* replotting; if every checked file fails to load,
  `plot_selected` clears the figure and returns at `:563` **without
  `canvas.draw()`**. Measured: a cleared-but-undrawn figure keeps showing
  the previous curves (buffer byte-identical). So mid-write autoreduce
  files leave the pre-refresh plot on screen under a "refreshed seconds
  ago" tooltip. Not blocking because the error dialogs are genuine
  disclosure. Two-line fix: `canvas.draw()` before the early return, and
  move the stamp to after `plot_selected()` returns.
- **F4** — in a `mixed` selection the `[kind]` legend suffix is applied
  only to *recognized* files (`:548`, `:592`), so the unrecognized file
  that caused the downgrade carries no annotation and the user cannot tell
  which file broke homogeneity.
- **F5** — `classify_file` opens with the locale encoding. Both
  `save_reduced_data.py` header variants emit `Å` (Å) at line 8,
  *above* the marker at line 13, so under a non-UTF-8 locale the decode
  raises and real reflectivity files classify `unknown` — B1's symptom,
  host-dependent. Use `encoding="utf-8", errors="replace"`. Also
  `if not line or not line.startswith("#")` treats a blank header line as
  end-of-block; `if line.strip() and not line.startswith("#")` is free
  robustness.
- **F6** — the corpus tuple lists five of the six tracked
  `reference_*.txt`; `reference_fbck.txt` is omitted (it classifies
  correctly). Glob `reference_*.txt` instead — all six are tracked, and the
  hand-list has already drifted by one.
